# Prior Git experience: loose, no formal flow

The learner has used Git "loosely" and has never used a formal branching workflow (no GitFlow, GitHub-flow, or TBD background). Teaching must start from the mental model of why a workflow exists at all, not assume any prior flow vocabulary.

Crucially, the learner's role is **director/reviewer/release-manager**, not committer — Claude Code does the implementation, commits, and PRs. So git-CLD fluency is low-priority; judgment about branch lifetime, PR size, releasability, and releases is the real target. See [[MISSION.md]].
