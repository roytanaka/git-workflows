Day-One Repo Setup — TBD Checklist

Do this once, before any feature code exists. It makes a trunk that many AI agents can target in parallel without breaking production. From Lesson 2.

1 · Repository basics

  • Trunk branch is mainOne shared mainline. This is the trunk.
  • Enable "Automatically delete head branches"Repo → Settings → General. Merged branches vanish (loop step ⑥).
  • Choose squash-merge as the default (recommended)One PR = one tidy commit on main; keeps trunk history readable and easy to revert.

2 · Protect main (ruleset or branch protection)

  • Require a pull request before mergingNo direct pushes. Every change — every agent — arrives as a PR.
  • Require status checks to passCI build + tests green before merge. Keeps the trunk others branch from green.
  • Require branches to be up to date before mergingPR must include latest main and be re-tested against it.
  • Require 1 approving reviewThe human gate — that approver is you.
  • Require conversation resolutionYour review comments can't be silently ignored.
  • Block force-pushes & deletions; no bypassRules apply to admins and bots too.

3 · CI (the checks you'll require)

  • Build passesThe app compiles / bundles.
  • Automated tests passSelf-testing build — the proof the trunk still works.
  • Lint / typecheckCheap, catches whole classes of agent mistakes before your review.

4 · Preview deploys

  • Connect host (Vercel/Netlify) to the repoAuto preview deployment per PR — your review surface (Lesson 4).

5 · Turn on later, when PR volume grows

  • Merge queueWhen several agents merge several PRs per day. Re-tests PRs combined against latest main — catches logical conflicts. A toggle in the same ruleset; no rework to add later.
Why day one? Once code and agents exist, retrofitting rules means fighting habits and history. Set the gate before the first PR and the entire workflow is correct "out of the gate" — every future change is funneled through one reviewed, tested doorway, no matter how many agents push at once.
